# Pipeline Backlog

GitHub Issues remain the primary actionable backlog. This directory documents conventions; it is not a second competing task database.

Before proposing a new issue, search:
- open and recently closed GitHub issues;
- open pull requests;
- `ISSUE_LOG.md` (including RES-* research entries);
- relevant `research/` notes and dependency records;
- `validation/` ledgers and scripts;
- `works-cited/index.html`.

A new issue must contain:

1. Precise question, defect, or proof obligation.
2. Evidence and exact repository paths or stable source links.
3. Affected theorem/claim/page/component.
4. Existing assumptions and dependencies.
5. One concrete next action.
6. Explicit closure criterion.
7. Current evidence classification and unresolved limitations.
8. Duplicate-check summary.

Do not create generic "investigate further" issues, duplicate the existing rewrite-polish scanner, or add tasks merely to keep the queue populated. If the issue is not sufficiently grounded, include it as an unverified lead in the run report instead.
